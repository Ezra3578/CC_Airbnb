\section{System Description}

In the present section, there will be a description of Airbnb system, 
which will take further the business problem it was designed to solve, as well as its 
main actors, and how they interact within the system described in the corresponding Use Cases.

Finally, there will be defined the System Boundaries, i.e, what is inside of the scope of our system
and what is explicitly outside of it.

% -------BUSINESS PROBLEM-------
\subsection{Business Problem}

The problem that Airbnb solves is referred to the fragmented, inefficient and uncertain access to short-term 
accomodations. It gives people who are in need of a place to stay, and people with those accomodations or 
properties available. The hosts might find problems finding or reaching potential guests, managing bookings 
and monetizing after all the stay, and guests might struggle finding said place.

Airbnb provides a platform in which guests are benefited with a large range and access of accomodation options, and hosts
can get additional income and a wider spectre of possible guests around the world.

Its operational challenge at scale, comes when one must maintain availibility accuracy (concurrence), transaction integrity,
trust, and service reliability accross a global two-sided marketplace. Also, there might be some problems taking compliance
into account.

% -------MAIN USE CASES-------

\subsection{Main Use Cases}

The following use cases were the most representative interactions of the system defined, focusing on the main business 
processes of the platform rather than technical operations performed by external services, i.e., supporting services 
such as the Payment Gateway, Maps Service, Authentication Service, and Notification Service participate in these use 
cases when required.

\subsubsection{Account Management}

\paragraph{Register}

\begin{itemize}
    \item \textbf{Actors:} Guest, Host, Authentication Service.
    
    \item \textbf{Preconditions:}
    \begin{itemize}
        \item The user does not already have an account with the provided credentials.
        \item The registration service is available.
    \end{itemize}
    
    \item \textbf{Main Flow:}
    \begin{enumerate}
        \item The user selects the registration option.
        \item The system requests the required registration information.
        \item The user provides the requested information.
        \item The system validates the information.
        \item The Authentication Service creates and validates the user credentials.
        \item The system creates the user account.
        \item The system confirms that the registration was successful.
    \end{enumerate}
    
    \item \textbf{Alternative Flows:}
    \begin{itemize}
        \item The provided information is invalid or incomplete.
        \item The provided email or credentials are already associated with an existing account.
        \item The Authentication Service is unavailable.
    \end{itemize}
    
    \item \textbf{Postconditions:}
    \begin{itemize}
        \item The user's credentials are registered with the authentication mechanism.
    \end{itemize}
\end{itemize}


\paragraph{Log In}

\begin{itemize}
    \item \textbf{Actors:} Guest, Host, Administrator, Customer Support, Authentication Service.
    
    \item \textbf{Preconditions:}
    \begin{itemize}
        \item The user has an existing account.
        \item The authentication service is available.
    \end{itemize}
    
    \item \textbf{Main Flow:}
    \begin{enumerate}
        \item The user enters their credentials.
        \item The system sends the credentials to the Authentication Service.
        \item The Authentication Service validates the credentials.
        \item The system creates an authenticated session.
        \item The system grants access according to the user's role.
    \end{enumerate}
    
    \item \textbf{Alternative Flows:}
    \begin{itemize}
        \item The credentials are invalid.
        \item The Authentication Service is unavailable.
    \end{itemize}
    
    \item \textbf{Postconditions:}
    \begin{itemize}
        \item The user is authenticated.
    \end{itemize}
\end{itemize}


\subsubsection{Accommodation Discovery}

\paragraph{Search Accommodation}

\begin{itemize}
    \item \textbf{Actors:} Guest, Maps Service.
    
    \item \textbf{Preconditions:}
    \begin{itemize}
        \item The accommodation search service is available.
    \end{itemize}
    
    \item \textbf{Main Flow:}
    \begin{enumerate}
        \item The guest enters a destination or location.
        \item The guest specifies optional dates, number of guests, and search criteria.
        \item The system queries available accommodations.
        \item The system applies the selected filters and criteria.
        \item The Maps Service provides geographical information when required.
        \item The system displays the matching accommodations.
    \end{enumerate}
    
    \item \textbf{Alternative Flows:}
    \begin{itemize}
        \item No accommodations match the search criteria.
        \item The requested location cannot be resolved.
    \end{itemize}
    
    \item \textbf{Postconditions:}
    \begin{itemize}
        \item The guest receives a list of accommodations matching the search criteria.
    \end{itemize}
\end{itemize}

\subsubsection{Reservation and Guest Experience}

\paragraph{Book Accommodation}

\begin{itemize}
    \item \textbf{Actors:} Guest, Host, Authentication Service, Payment Gateway, Notification Service.
    
    \item \textbf{Preconditions:}
    \begin{itemize}
        \item The guest is authenticated.
        \item The accommodation is active.
        \item The selected dates are available.
    \end{itemize}
    
    \item \textbf{Main Flow:}
    \begin{enumerate}
        \item The guest selects an accommodation and dates.
        \item The system verifies availability.
        \item The system calculates the reservation price.
        \item The guest confirms the reservation.
        \item The system requests payment processing.
        \item The Payment Gateway processes the transaction.
        \item The system creates the reservation.
        \item The system updates the accommodation availability.
        \item The Notification Service sends the reservation confirmation.
    \end{enumerate}
    
    \item \textbf{Alternative Flows:}
    \begin{itemize}
        \item The accommodation becomes unavailable before confirmation.
        \item The payment is rejected.
        \item The payment remains pending.
        \item The reservation cannot be created.
    \end{itemize}
    
    \item \textbf{Postconditions:}
    \begin{itemize}
        \item The reservation is registered with its corresponding status.
        \item The accommodation availability is updated.
        \item The guest and host receive the corresponding notification.
    \end{itemize}
\end{itemize}


\paragraph{Cancel Reservation}

\begin{itemize}
    \item \textbf{Actors:} Guest, Host, Payment Gateway, Notification Service.

    \end{itemize}

    \begin{enumerate}

        \item The system verifies the cancellation conditions.
        \item The system changes the reservation status.
        \item The system updates the accommodation availability.
        \item The system determines whether a refund is applicable.
        \item The Payment Gateway processes the refund when applicable.
        \item The Notification Service sends the cancellation notification.
    \end{enumerate}
    
    \item \textbf{Alternative Flows:}
    \begin{itemize}
        \item The reservation cannot be cancelled under its current conditions.
        \item The refund cannot be processed.
        \item The cancellation notification cannot be delivered.
    \end{itemize}
    
    \item \textbf{Postconditions:}
    \begin{itemize}
        \item The reservation is marked as cancelled.
        \item The accommodation availability is updated.
        \item The applicable refund is registered.
    \end{itemize}
\end{itemize}

% -----BOUNDARIES-----
\subsection{System Boundaries}

The system boundary is defined around the core rental marketplace, including the capabilities required to 
publish, discover, and manage rental agreements between hosts and guests. The system includes rental information such 
as pricing, dynamic pricing rules, dates, check-in and check-out agreements, terms of use, and specific guest conditions. 
It also includes the host interface for publishing and managing properties, including percentage-based charges, and 
the guest interface for searching and reviewing available rentals. The system must also provide authentication and 
security, as well as the raw rental listing required to support the marketplace. Map-based catalog visualization, 
system filters, and favorites are considered within the boundary as secondary capabilities that support the accommodation 
discovery process.

The boundary also includes capabilities classified as ``Could Have'' where they involve the platform's own 
operational functionality, particularly administration, monitoring, and auditing, including the visualization of 
external transactions. Customer support is likewise considered within the system boundary, although it is not part of 
the fundamental rental workflow. The payment gateway, however, is treated as an external system: payment integration 
may be included as a future capability, but the actual financial transaction processing is performed outside the system. 
Similarly, external authentication or other third-party services may interact with the platform without becoming part 
of its internal scope.

The system explicitly excludes cleaning, maintenance, and other third-party property services, which were classified 
as ``Won't Have''. These activities may be relevant to the real-world rental process, but they are not managed by the 
application itself. More generally, the system boundary ends at the point where an external organization or service 
performs an operational activity that the application does not manage. The details of each included capability, including 
its functional behavior and requirements, will be specified later in the functional requirements section.
